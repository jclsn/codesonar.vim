==============================================================================
1. INTRODUCTION                                        *codesonar-introduction*

Shows the warnings of CodeSonar analyses in the code, from a CodeSonar hub
or from an exported SARIF file.

The work is done by the codesonar-lsp language server: it talks to the hub,
moves warnings along with the code while it is edited and hides warnings
whose code changed since the analysis, because they are usually fixed. This
plugin registers the server with yegappan/lsp and adds commands for what
LSP has no counterpart for: choosing analyses, signing in to the hub and
running analyses.

The warnings are regular diagnostics, so the commands of yegappan/lsp work
for them, e.g.: >

	:LspDiag next		go to the next warning
	:LspDiag current	show the warning at the cursor
	:LspHover		explain the warning at the cursor
	:LspCodeAction		apply a fix, explain the warning or open it
				on the hub
<
Requirements: Vim 9.1, yegappan/lsp and the codesonar-lsp server in $PATH.
|:CodeSonarAnalyze| needs the CodeSonar command line tools.

==============================================================================
2. SETUP                                                      *codesonar-setup*

Install the server from the codesonar-lsp repository: >

	cargo install --path .
<
Configure the server like your other language servers of yegappan/lsp, in
|g:codesonar|, e.g. in ~/.vim/lsp/codesonar.vim: >

	let codesonar = #{
	      \ name: 'codesonar',
	      \ path: 'codesonar-lsp',
	      \ initializationOptions: #{
	      \   hub: #{
	      \     url: 'http://nas:7340',
	      \     username: 'lspuser',
	      \     passwordFile: '~/.config/codesonar/password',
	      \   },
	      \ },
	      \ }
	call LspAddServer([codesonar])
<
The plugin adds its handlers to the entry before yegappan/lsp starts the
server, so define it in your vimrc, not later. Without g:codesonar, the
plugin registers a server without settings itself, e.g. for
|:CodeSonarConnect|.

The server shows the newest finished analysis of the hub project of the
workspace. Without hub.project, it detects the project: from the project
files of an earlier analysis, like "mixxx.prj_files", else by the name of
the workspace folder. To show an exported SARIF file instead: >

	initializationOptions: #{sarifFile: 'codesonar.sarif'}
<
The server starts with the first C or C++ file of a workspace. The workspace
is the closest directory above the file with a "codesonar.conf", a
".codesonar" or a ".git".

==============================================================================
3. COMMANDS                                                *codesonar-commands*

The commands need a running server, so use them in a file of the workspace.

:CodeSonarAnalyses                                        *:CodeSonarAnalyses*
		Open a menu with the analyses of the hub project, newest
		first. The shown analysis is marked with "*". <CR> shows the
		chosen analysis and closes the menu. <Space> shows it and
		keeps the menu open, so you can try another one; on the shown
		analysis, it hides it like |:CodeSonarToggle|. An analysis
		that is loading is marked with "~".

		Finished analyses are kept downloaded once they were shown,
		see cachedAnalyses in |codesonar-settings|, and marked with
		"[cached]": they show up quickly. "x" deletes the local copy,
		so that the analysis is downloaded again the next time.

		"d" deletes the analysis from the hub after you confirm with
		"y". If it was shown, the newest finished analysis is shown
		instead. If the hub user may not delete analyses, a message
		says so. The keys are shown below the analyses.

:CodeSonarAnalyze [name]                                  *:CodeSonarAnalyze*
		Run "codesonar analyze" for the workspace in a vertical
		terminal split. When it succeeds, the new analysis is shown.
		[name] names the analysis on the hub.

:CodeSonarExplain                                          *:CodeSonarExplain*
		Explain the warnings in the cursor line in a popup, like the
		"Show details" code action: the message, the events that
		lead to the warning, numbered as on the hub, and the rules of
		coding standards it may violate. The titles of the rules come
		from the hub. Other popups are closed. In the popup:
			j k <C-D> <C-U> g G	scroll
			o			open the warning on the hub
			d			open the documentation
			q <Esc>			close
		Moving the cursor closes it as well.

:CodeSonarConf                                                *:CodeSonarConf*
		Open the configuration file of the workspace in a split, e.g.
		to add WARNING_FILTER rules: codesonar.conf in its root, see
		|codesonar-incremental|. Without it, open the configuration
		file of the CodeSonar project. If there is none yet, it is
		created from the template.conf of CodeSonar, as the first
		analysis would.

:CodeSonarConnect [url [user]]                            *:CodeSonarConnect*
		Sign in to a hub, asking for the password, and choose one of
		its projects. Without arguments the configured hub is used.

:CodeSonarPresets [preset ...]                            *:CodeSonarPresets*
		Choose the CodeSonar presets of |:CodeSonarAnalyze|, e.g.
		"misrac2025" for the rules of MISRA C:2025. Without arguments,
		a menu shows the presets of the installation with their
		descriptions:
			j k <C-D> <C-U> g G	move
			<Space>			tick or untick a preset
			<CR>			use the ticked presets
			q <Esc>			cancel
		With arguments, analyses use these presets. The choice lasts
		until Vim exits; to keep it, set analyze.presets in the
		settings of |g:codesonar|. The shown analysis stays.

:CodeSonarProjects                                        *:CodeSonarProjects*
		Choose another project of the hub.

:CodeSonarLoad [file]                                         *:CodeSonarLoad*
		Show the SARIF file [file], else the configured analysis.

:CodeSonarDiagnostics                                  *:CodeSonarDiagnostics*
		Fill the quickfix list with the shown warnings and open it.
		The list is updated when another analysis is shown.

:CodeSonarOpenHub                                          *:CodeSonarOpenHub*
		Open the warning at the cursor on the hub, or else the shown
		analysis.

:CodeSonarRefresh                                          *:CodeSonarRefresh*
		Load the shown analysis again.

:CodeSonarStatus                                            *:CodeSonarStatus*
		Show the status in a popup: the shown analysis with its page
		on the hub, how many of its warnings are unchanged, moved,
		changed and unverified, and the hub and presets of new
		analyses. "o" opens the analysis on the hub, "q" closes the
		popup.

:CodeSonarToggle                                            *:CodeSonarToggle*
		Turn the shown analysis off: its warnings disappear until you
		turn it on again with |:CodeSonarToggle|, or show another one,
		e.g. with |:CodeSonarAnalyses| or |:CodeSonarLoad|.

Example mappings: >

	nnoremap <Leader>ca <Cmd>CodeSonarAnalyses<CR>
	nnoremap <Leader>cd <Cmd>CodeSonarDiagnostics<CR>
	nnoremap <Leader>co <Cmd>CodeSonarOpenHub<CR>
	nnoremap <Leader>ce <Cmd>CodeSonarExplain<CR>
<
The User event CodeSonarLoaded is triggered when an analysis was shown.

                                                 *codesonar#Progress()*
codesonar#Progress() returns what the server is busy with, for the status
line, e.g. "CodeSonar ⠹ Downloading 4.2 MB". It is empty while the server
is idle. Large analyses take a minute to download, because the hub creates
them while sending them. The spinner turns while the server is busy.

With vim-airline, the progress is shown in section c, after the file name.
With lightline, it is the leftmost component on the right, unless
g:lightline.component_function has a "codesonar" component already. A
plain 'statusline' needs the function: >

	set laststatus=2
	set statusline=%f\ %h%m%r%=%{codesonar#Progress()}\ \ %l,%c%V\ %P
<
                                                     *codesonar-incremental*
|:CodeSonarAnalyze| passes codesonar.conf in the root of the workspace to
CodeSonar with -conf-file, if it exists. CodeSonar reads it after the
configuration of the project, so it only needs the settings that differ,
e.g.: >

	INCREMENTAL_BUILD = Yes
	WARNING_FILTER += discard path:/build/
<
Analyses are incremental unless INCREMENTAL_BUILD is "No" in one of the
files: each one is a child of the previous and only needs what was
compiled since then. So the first analysis builds with
analyze.buildCommand ("make -B"), later ones with
analyze.incrementalBuildCommand ("make"). After you changed files,
|:CodeSonarAnalyze| updates the analysis with just these files.

                                                       *codesonar-highlight*
The explanation popup uses these highlight groups, linked by default to the
group in parentheses:

CodeSonarExplainTitle		warning class (Title)
CodeSonarExplainRule		ids of warning classes and rules (Identifier)
CodeSonarExplainHeading		headings (Statement)
CodeSonarExplainLabel		link labels (Statement)
CodeSonarExplainChanged		note on changed code (WarningMsg)
CodeSonarExplainUrl		URLs (Underlined)
CodeSonarExplainFunction	function calls like printf() (Function)
CodeSonarExplainNumber		numbers (Number)
CodeSonarExplainQuoted		quoted names like 'p' (String)
CodeSonarExplainCode		`code` (Special)
CodeSonarExplainBold		**bold** (bold)
CodeSonarExplainLocation	file locations like main.c:16 (Directory)
CodeSonarExplainSeparator	line between warnings (NonText)
CodeSonarExplainHint		key hints (Comment)

The status popup of |:CodeSonarStatus| uses these groups:

CodeSonarStatusTitle		title (Title)
CodeSonarStatusLabel		labels like "Analysis" (Statement)
CodeSonarStatusNone		missing values and the analysis id (Comment)
CodeSonarStatusUrl		the page of the analysis (Underlined)
CodeSonarStatusNumber		numbers of warnings (Number)
CodeSonarStatusUnchanged	unchanged warnings (String)
CodeSonarStatusMoved		moved warnings (Identifier)
CodeSonarStatusChanged		changed warnings (WarningMsg)
CodeSonarStatusUnverified	unverified warnings (Comment)
CodeSonarStatusPreset		presets (Identifier)
CodeSonarStatusHint		key hints (Comment)

The menus of |:CodeSonarAnalyses| and |:CodeSonarConnect| show their keys
below the items:

CodeSonarMenuKey		keys like <CR> (Special)
CodeSonarMenuHint		what the keys do (Comment)

The preset menu of |:CodeSonarPresets| highlights the names of presets:

CodeSonarPresetName		presets that are not ticked (Identifier)
CodeSonarPresetTicked		ticked presets (Special)

==============================================================================
4. SETTINGS                                                *codesonar-settings*

                                                              *g:codesonar*
g:codesonar is the server entry of yegappan/lsp, see |lsp-server-add|. The
plugin completes it with these defaults:

name		"codesonar"
path		"codesonar-lsp"
filetype	["c", "cpp"]
rootSearch	["codesonar.conf", ".codesonar", ".git"]

and with its handlers in customNotificationHandlers and
customRequestHandlers. Further keys are settings of the plugin:

browser		Command that opens hub links. Default: Vim's |:Open|.
statusline	Add the progress to the status line of vim-airline and
		lightline, see |codesonar#Progress()|. Default: true.

initializationOptions holds the settings of the server, see the README of
codesonar-lsp.

The most common server settings:

hub.url		Hub URL, e.g. "http://nas:7340".
hub.username	Hub user. Empty for anonymous access.
hub.passwordFile
		File with the hub password. Without it, $CODESONAR_PASSWORD
		is used.
hub.project	Hub project whose analyses are shown.
sarifFile	Local SARIF export, used without a hub.
cachedAnalyses	How many shown analyses of each hub project are kept
		downloaded, in cacheDir ($XDG_CACHE_HOME/codesonar-lsp). 0
		turns this off. Default: 10.
pathMappings	Paths from the analysis machine to local paths, e.g.
		[{from: '/builds/app', to: '/home/me/src/app'}].
changed		Warnings in code changed since the analysis: "hide" (the
		default) or "mark" to show them as hints.
analyze.buildCommand
		Build command of |:CodeSonarAnalyze|. It builds everything,
		since CodeSonar only sees what is compiled. Default: "make -B".
analyze.incrementalBuildCommand
		Build command of incremental analyses, see
		|codesonar-incremental|. Default: "make".
analyze.confFile
		Configuration file of the workspace, see
		|codesonar-incremental|. Default: "codesonar.conf".
analyze.presets	CodeSonar presets of |:CodeSonarAnalyze|, e.g.
		['misrac2025', 'cert'].
analyze.projectFile
		Project prefix, relative to the workspace: CodeSonar names the
		project files after it, e.g. "prefix.conf". Default:
		".codesonar/project".
